## 0. 本文档怎么用

1. **本文档是后续所有开发对话的执行依据**。新对话开始时，先读第 4 章「阶段总览」确认当前所处阶段，再读该阶段的详细设计章节，只实现该阶段范围内的内容。
2. **禁止跨阶段实现**。若发现后续阶段的能力是当前阶段的前置条件，先把前置部分拆到当前阶段并在本文档登记，不要提前把后面阶段的表和功能一起做掉。
3. **每完成一个任务项，必须回写本文档**：把第 4 章总览表与对应阶段任务表中的 `状态` 列由 `待开始` 改为 `进行中` / `已完成`，并在第 9 章「变更记录」追加一行，写明日期、阶段、完成内容、验证方式。
4. **禁止只改文档不改实现，也禁止只改实现不验证**。每个阶段收尾必须给出：接口自测记录、页面实测记录、数据库变更脚本、指标复算结果。
5. 七鱼有的功能我们原则上都要有；**确实不做的，必须在第 1.4 节写明取舍理由**，新增不做项也要写进去，不允许口头砍需求。
6. 字段级设计以本文档第 5 章为准；表结构落地后必须同步更新 [数据库设计.md](数据库设计.md) 的表字典与 ER 图，两份文档不一致时以 `sql/` 下的脚本为事实来源，并立刻修正文档。

### 0.1 状态标记约定

| 标记 | 含义 |
| --- | --- |
| `待开始` | 尚未动工 |
| `进行中` | 已开始，未完成 |
| `已完成` | 代码 + 数据库 + 前端 + 自测全部通过 |
| `已阻塞` | 被外部条件卡住，必须在任务后注明阻塞原因 |
| `不做` | 明确放弃，必须在第 1.4 节登记理由 |

### 0.2 优先级定义

| 级别 | 含义 | 判定标准 |
| --- | --- | --- |
| P0 | 商业化闭环必须 | 缺了它无法向客户交付、无法收费，或存在数据错误/资金风险 |
| P1 | 竞争力必须 | 客户选型对比七鱼时会直接问到的能力 |
| P2 | 增值与差异化 | 提升客单价、提升续约率，但不影响成单 |
| P3 | 长线储备 | 生态、开放平台、行业化能力 |

## 1. 对标基准：网易七鱼能力全景

### 1.1 七鱼产品模块与官方口径

网易七鱼对外提供 7 大模块：**在线客服、在线机器人、云呼叫中心、视频客服、工单系统、智能质检、数据大屏**，外加贯穿各模块的**坐席辅助**与**知识库运营**能力。官方公开口径中的关键数字（作为我们的目标参照，不作为承诺）：

| 指标 | 七鱼公开口径 | 我们的阶段目标 |
| --- | --- | --- |
| 机器人问题解决率 | 80% ~ 91.8% | S1 结束 ≥ 60%，S5 结束 ≥ 75% |
| NLP 意图识别率 | 95% | 以「知识库直答 + 参考生成」命中率口径统计，S1 结束 ≥ 85% |
| 智能纠错准确率（质检） | 95%+ | S5 结束人工复核一致率 ≥ 90% |
| 坐席辅助节省人力 | 70%+ | S2 结束平均会话时长下降 ≥ 20% |
| 知识库维护成本下降 | 90%（行业知识云冷启动） | S1 提供行业知识包导入，冷启动时间 ≤ 1 天 |

## 3. 指标口径定义（商业化必须固化）

> 所有对外展示、对客户承诺、对内部绩效管理的数字，一律使用本节口径。口径变更必须同步修改本节并在第 9 章登记。

| 指标 | 定义 | 计算方式 | 排除项 | 行业参考 |
| --- | --- | --- | --- | --- |
| 首次响应时长 | 访客发出第一条**有效**消息，到坐席/AI 首次给出**有效回复**的时间差 | `first_reply_time - first_user_msg_time`，取均值与 P90（**S6-A 已落地**：R-177 输出 `avgFirstResponseSeconds` / `p90FirstResponseSeconds` / `firstResponseSample`） | 系统自动欢迎语不计入回复；访客连续多条消息只按第一条计时 | 头部 ≤ 10s，大促 ≤ 15s |
| 3 分钟回复率 | 会话内**每一轮**访客消息，坐席在 3 分钟内回复的比例 | 按轮次统计，不按会话统计；**S6-A 已落地**：只统计人工接待期（`accept_time ~ end_time`）内 USER 消息与其后首条 AGENT 回复，秒差 ≤180s 计命中，会话关闭时固化到 `chat_session.reply_round_count` / `reply_3min_count` | AI 自动应答轮次单列，不混入人工回复率 | ≥ 99% |
| AI 自主解决率 | 未接入人工即关闭的会话占已关闭会话的比例 | `agent_id IS NULL AND status='CLOSED'` / `status='CLOSED'` | 访客主动放弃且未评价的会话需单列，不直接算解决 | 60% ~ 80% |
| 一次性解决率 | 访客问题在 72 小时内未二次进线的比例 | 按访客身份（`chat_session.user_id`）归并，72h 窗口内无新会话即算解决；**S6-B 已落地**：R-177 输出 `oneTimeResolveRate` 与 `oneTimeResolveBase` / `oneTimeResolveCount` / `revisitCount`，分母仅取「结束时间早于 `now-72h`」的可观察会话，避免窗口未满被误判为已解决 | 无法识别身份的匿名访客不参与统计；AI 接待且未接人工的会话不计入分母 | ≥ 95% |
| 知识库命中率 | AI 应答轮次中，命中知识库（直答或作为参考注入）的比例 | `(kb-direct + reference) / 全部 AI 应答轮次` | 兜底话术轮次计入分母不计入分子 | ≥ 85% |
| 转人工率 | 触发转人工的会话占全部会话比例 | `转人工会话数 / 会话总数` | 机器人主动引导但访客未点击的不计 | 行业 20% ~ 40% |
| 满意度（CSAT） | 会话或工单的 1~5 星评分均值 | `AVG(rating)` | **必须同时披露回收率** = 评价数 / 已关闭会话数 | ≥ 4.5 且回收率 ≥ 30% |
| 工单首响时长 | 工单创建到处理人首次回复/流转的时间差 | 基于 `work_order_log` 首条非 CREATE 动作 | 「等待客户反馈」期间停表 | 按优先级分档 |
| 工单解决时长 | 工单创建到 `RESOLVED` 的时间差 | 扣除停表时长 | 客户驳回重开的重新计时 | 按优先级分档 |
| 工单超时率 | `overdue_flag=1` 占全部工单比例 | `SUM(overdue_flag=1)/COUNT(*)` | — | ≤ 5% |
| 质检合格率 | 质检得分 ≥ 阈值的会话占比 | `合格会话 / 已质检会话` | 抽样质检需注明抽样比例 | ≥ 90% |
| 人机复核一致率 | 人工复核结论与自动质检结论相同的记录占比 | 样本 = 区间内 `status ≠ PENDING` 的记录，`一致记录数 / 已复核记录数`（复核分 − 自动分 = 0 计一致） | 待复核与已驳回退回的样本不计入 | 目标 ≥ 90%（S5 结束口径，见 1.1） |
| 排队放弃率 | 排队中主动离开或超时关闭的会话占进入排队会话比例 | `close_reason IN ('TIMEOUT','USER_LEAVE') AND 曾进入 WAITING` | — | ≤ 10% |

绩效建议按三组联动，避免单指标造假：**效率组**（首响、3 分钟回复率、平均会话时长）、**质量组**（满意度、质检合格率、一次性解决率）、**业务组**（AI 自主解决率、转人工率、工单超时率）。
